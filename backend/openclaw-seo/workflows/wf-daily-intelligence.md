# Workflow: Daily Intelligence

**Cadence:** Background — runs independently of the report and plan pipeline
**Trigger:** Delta-eval Step 4c — only after report exists and weekly plan is in place (or queue is idle)
**Priority:** normal (never critical)
**Persona:** You are the Data Intelligence Gathering Agent. You are meticulous, silent, and strictly analytical.

## Purpose

This workflow collects WoW performance data between report cycles. It exists to detect anomalies (rank drops, traffic drops, crawl spikes) so the orchestrator can respond quickly — not to gate or unblock any other workflow.

**This workflow is NOT a prerequisite for report generation.** The research-analyst generates reports from `about/` files and public research. This snapshot enriches reports when available but never blocks them.

## Task Steps

1. Read the company's `profile.md` to identify the primary domain and active tools.
2. Collect performance data using the browser-first approach (see agents/data-intelligence.md for the canonical data collection sequence):
   - **GSC capability**: If `GOOGLE_SERVICE_ACCOUNT_JSON` + `GSC_SITE_URL` present → API call; absent → write `[Data Missing: No GSC Key]`
   - **GA4 capability**: If `GA4_PROPERTY_ID` + `GOOGLE_SERVICE_ACCOUNT_JSON` present → API call; absent → write `[Data Missing: No GA4 Key]`
   - **SERP / keyword positions**: If `SERPER_API_KEY` present → serper-miner; absent → WebSearch manual SERP check with `[Source: manual SERP check — no rank tracking API]`
   - **Core Web Vitals**: Always → WebFetch `https://pagespeed.web.dev/report?url=<company_url>` with `[Source: Google PageSpeed public API]`
   - **Index status**: Always → WebSearch `site:<domain>` with `[Source: Google index check via WebSearch]`
   - **URL health**: Always → WebFetch each tracked URL; verify HTTP 200
   - Do not abort the snapshot because one credential is missing — write what you can.
3. Pipe the collected data into the snapshot classification format (see below).
4. Write results to `technical/current-snapshot.md` (overwrite).
5. Append any anomalies to `data-intelligence/anomalies-log.md`.
6. Mark the task `completed` with `data_available: true/false` in the result.

**Company**: {slug}

**Status**: {ACTIVE|PAUSED}

| Metric | Value | WoW Delta | Trend |

3. **[MEDIUM]** {description}

*Generated by data-intelligence agent via wf-daily-intelligence*

**Rules:**
- Use `## Search Console (GSC)` as the exact section header for GSC data.
- Use `## Analytics (GA4)` as the exact section header for GA4 data.
- Use `### Top Pages by Clicks` for page performance tables.
- Use `### Top Queries by Clicks` for query performance tables.
- Use `## Keyword Rankings` for ranking data.
- Use `## Action Items` with numbered `[CRITICAL/HIGH/MEDIUM/LOW]` items.
- Always overwrite — do not append to the file.
- Run once per day or on task updates. The orchestrator manages cadence.

## Skills Attached

> This workflow uses browser-first data collection. Private API skills (gsc-fetch, ga4-fetch, rank-track) are stubs that return hardcoded data — they are NOT injected here. See `agents/data-intelligence.md` for the canonical browser-first data collection sequence, and `references/task-statuses.md` for the stub skill policy.
